# Pitfall: hand-crafted `.obsidian/workspace.json` breaks Obsidian

## Symptom
Obsidian throws an error / refuses cleanly when opening a vault whose `.obsidian/workspace.json`
was written by hand in a simplified shape.

## Broken form (DO NOT USE)
```json
{
  "main": { "type": "leaf", "state": { "type": "graph" } },
  "left": { "type": "split", "state": { "type": "sidebar", "collapsed": false } },
  "right": { "type": "split", "state": { "type": "sidebar", "collapsed": false } }
}
```
This was authored manually and caused the user-visible Obsidian open-error.

## Valid form
Copy the FULL config from a known-good working vault. Structure (top-level keys):
`["main", "left", "right", "left-ribbon", "active", "lastOpenFiles"]` where `main` is a
`"type":"split"` with `children` (tabs → leaves), and each leaf `state` has an `"id"` etc.
Reference working vault: `C:\Users\Unicorn\Documents\Obsidian Vault\.obsidian\workspace.json`.

## Fix (applied this session)
Replaced the broken `workspace.json` in every profile vault
(`Documents/Obsidian-Profiles/{default,app,marketplace}`) with a copy of the working vault's
`workspace.json`. Then changed `lib-profile-graph.sh` so new profiles COPY the full valid config
(`app.json`, `workspace.json`, `core-plugins.json`, `appearance.json`, `graph.json`) from the
working vault instead of generating any of them.

## Rule
Never author Obsidian `.obsidian/*` JSON by hand. Always derive from an existing working vault.
Other files (`core-plugins.json`, `graph.json`, `appearance.json`, `app.json`) generated by
Obsidian itself were fine — only the hand-written `workspace.json` was the problem.
