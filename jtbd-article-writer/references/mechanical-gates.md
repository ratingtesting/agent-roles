# Механические гейты CJM-цепи статей

Проверка готовой цепи СКРИПТОМ, а не чтением модели: один прогон на всю цепь, единый вердикт, около секунды на статью. Скрипт кладётся в папку этапа (например `check_gates.py`), запускается как
`python check_gates.py --chain <id> --dir <папка со статьями>` и пишет отчёт `GATES_<chain>.md`.

## Как устроен скрипт
- Собирает статьи по папкам, сортирует по номеру из имени файла, читает карту ролей (leaf/mid/trunk) и индексов из JSON цепи.
- Текст статьи для проверок = статья без нижнего индекс-блока (`<!-- ARTICLE_INDEX_JSON ... -->` и ниже) — иначе гейты ловят собственные служебные поля.
- Картинки и подписи вырезаются из текста перед проверкой клише и объёма.
- Результат: список ОШИБОК (нарушения канона) и ПРЕДУПРЕЖДЕНИЙ (калибруются на реальных текстах).

## ОБЯЗАТЕЛЬНЫЕ ПРОВЕРКИ (ошибка)
1. **Индекс-блок.** Есть `ARTICLE_INDEX_JSON`, он парсится, в нём все поля карточки (chain_id, article_index, node_role, source_phrase, cjm_stage/funnel, thought, emotion, objection, barrier, pain, info_sought, content_angle, tail, transition_to_next, next_article_index, cta, geo).
2. **Совпадение индексов.** `article_index` равен номеру в имени файла; `next_article_index` существует в цепи (или null у последней).
3. **Кнопка-переход.** У всех статей кроме финальной — `[→ Статья <n>: <H1>](article_<n>.md)`.
4. **Год.** Текущий год (n) — 0 вхождений; допустим только n+1.
5. **Месяцы.** Ни одного названия месяца нигде (включая заголовки и подписи).
6. **Продукты не в продаже.** Упоминания клубов/сообществ/подписок — 0.
7. **Нумерация.** «статья N», «часть N», «№ N» в тексте статьи — 0 (кроме кнопки-перехода и индекс-блока).
8. **Концовки-анонсы.** «в следующей статье», «в следующей части», «дальше будет», «перейдём к» — 0.
9. **Цены.** «стоимость услуги/гайда/сопровождения», «N% от стоимости», «минимум N тыс/руб», «цена гайда» — 0. Ссылка оплаты: ровно одна на цепь и только в финальной статье.
10. **Продажа по стадиям.** Упоминания гайда/услуги/консультации в статьях до статьи сравнения и в первых абзацах любой статьи — нарушение (в первых 3 абзацах — запрет безусловный).
11. **Клише.** Чёрный список русских ИИ-штампов («в современном мире», «не секрет, что», «каждый знает», «важно понимать», «стоит отметить», «таким образом», «в заключение», «осуществляется», «является», «в рамках», «в этой статье мы разберём», «давайте разберёмся», «на сегодняшний день», «инновационный», «бесшовный», «комплексный подход») — 0. Самый сильный маркер ИИ — списки «**Термин:** описание»: считать предупреждением и переписывать прозой.
12. **Имена картинок.** В каждом пути картинки есть `article_<индекс>_`; файл физически существует рядом со статьёй; количество совпадает с ролью (лист 1, середина 2, финал 3).

## ПРЕДУПРЕЖДЕНИЯ (калибровать по реальным текстам)
13. **Объём.** Лист 800–1100, середина 1200–1500, финал 900–1300; допуск ±15%, дальше — флаг.
14. **Meta.** Нет Meta title / Meta description / keywords — флаг. Распознавать варианты оформления (`Meta Title:`, `SEO title`, `Title:`, `Description:`, `Keywords:`/`Ключевые слова`) — модели ставят их по-разному, и узкий regex даёт ложное «мета нет». Если мета и картинки отсутствуют у ВСЕГО блока карточек одной карточки (не у отдельных статей) — это фейл карточки, а не опечатка: докладывать владельцу как «блок закрылся формально» (замерено: один блок из трёх выдал 386–585 слов без мета и без сгенерированных картинок, два других — в норме).
15. **Легенда.** В первом абзаце есть слова юридических механик (справка, выписка, Росреестр, нотариус, обязательство, согласие супруга, пошлина, ЕГРН) — флаг: легенду переводить на бытовую сцену.
16. **Гео.** Для цепей с географией — список разрешённых районов и список «чужих» районов; чужой район в примерах = ошибка; район вне списка = предупреждение. Списки задавать на цепь.
17. **Цифры.** Все числа с `%`, `млн`, `тыс`, `руб` из статей сверять с числами гайда и доменного файла фактов; чего нет в источниках — флаг «проверить вручную». Это единственный надёжный способ поймать выдуманную цифру без чтения модели.
18. **Ключевая фраза.** Первые ~900 слов должны содержать фразу листа (заголовок строится из запроса дословно).

## Порядок применения
- **Перед первой пользой прогнать гейт на ЗАВЕДОМО ПЛОХОЙ партии (тексты прошлой итерации) и убедиться, что каждое правило СРАБАТЫВАЕТ.** Гейт, молчащий из-за кривого regex, даёт ложно-зелёный вердикт и подписывает брак; на живой партии без индекс-блоков скрипт поднял 26 ошибок (нет `ARTICLE_INDEX_JSON`, нет кнопок-переходов, имя картинки без индекса, месяц, продажа в первых абзацах, легенда на ЕГРН) — это доказательство инструмента, а не текстов.
- Гейт запускается ПОСЛЕ пилота на одной цепи и ДО масштабирования на остальные: сначала проверяем скрипт на живых текстах, калибруем ложные срабатывания (омонимы месяцев, гео-списки), только потом гоним все цепи.
- Ошибки исправляет автор текста (или отдельная карточка-правка), а не гейт: скрипт только фиксирует адрес нарушения (статья + правило).
