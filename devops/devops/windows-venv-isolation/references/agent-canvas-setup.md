# Agent Canvas on Windows — full setup recipe

## Prerequisites

- Hermes desktop app (v0.19.0+)
- Windows 11
- CPU without AVX2 (Xeon E5-2696 v3): all native binaries need baseline builds
- Agent Canvas Desktop Installer (exe from GitHub Releases)

## Three blockers and their fixes

### 1. PYTHONPATH leak (pydantic crash)

Hermes exports `PYTHONPATH=...hermes-agent/venv/Lib/site-packages`. The
uvx-spawned agent-server loads pydantic from the Hermes venv instead of
the uv cache → `ModuleNotFoundError: No module named 'pydantic_core._pydantic_core'`.

**Fix:** strip PYTHONPATH before launching:
```powershell
$env:PYTHONPATH = ''
Start-Process -FilePath 'C:\Users\<user>\AppData\Local\Programs\Agent Canvas\Agent Canvas.exe'
```
Or in git-bash: `export PYTHONPATH="" && "path/to/Agent Canvas.exe"`

### 2. IPv4/IPv6 localhost mismatch

On this Windows 11 machine, `localhost` resolves to `::1` (IPv6) first.
The agent-server binds to `127.0.0.1:18000` (IPv4) only. The ingress
proxy (`dev-with-automation.mjs`) uses `http://localhost:18000` for
routes, so Node.js resolves to `::1:18000` → `ECONNREFUSED`.

**Fix — patch the app's scripts:**

File: `resources/app/scripts/dev-with-automation.mjs`
(relative to `%LOCALAPPDATA%\Programs\Agent Canvas\`)

Replace `http://localhost:${config.agentServerPort}` with
`http://127.0.0.1:${config.agentServerPort}` in three places:

1. Agent-server route building (for/in loop):
   ```javascript
   routes.push([prefix, `http://127.0.0.1:${config.agentServerPort}`]);
   ```
2. Automation backend route:
   ```javascript
   routes.push([AUTOMATION_ROUTE_PREFIX, `http://127.0.0.1:${config.autoBackendPort}`]);
   ```
3. Automation env variable:
   ```javascript
   AUTOMATION_AGENT_SERVER_URL: ... || `http://127.0.0.1:${config.agentServerPort}`,
   ```
4. Secrets seeding URL:
   ```javascript
   const url = `http://127.0.0.1:${config.agentServerPort}/api/settings/secrets`;
   ```
5. Server info health check:
   ```javascript
   `http://127.0.0.1:${config.agentServerPort}/server_info`,
   ```

After patching, verify with: `curl http://localhost:8000/server_info`
should return JSON (not ECONNREFUSED).

### 3. Stale processes on ports

Agent Canvas uses ports 8000 (ingress), 3001 (static), 18000 (agent-server),
18001 (automation). After a crash or restart, previous instances may
linger.

**Fix — kill via port:**
```bash
for pid in $(netstat -ano | grep -E "8000|18000|3001|18001" | grep LISTEN | awk '{print $5}'); do
  taskkill /F /PID $pid
done
```

Also check for FlashRank on port 8000 (conflicts with ingress).

## Port map

| Service | Port | Process | Protocol |
|---|---|---|---|
| Ingress proxy (UI) | 8000 | Node.js | HTTP |
| Static frontend | 3001 | Node.js | HTTP |
| Agent-server | 18000 | Python/uvicorn | HTTP |
| Automation backend | 18001 | Python/uvicorn | HTTP |

## First-launch sequence

1. Electron app starts → checks port availability
2. Spawns agent-server via uvx (takes ~30-40s for Python load)
3. Spawns automation backend via uvx
4. Spawns static frontend server (Node.js)
5. Spawns ingress proxy (Node.js)
6. Waits for agent-server `/server_info` to respond
7. Seeds API key via PUT /api/settings/secrets
8. UI opens at http://localhost:8000

If step 6 or 7 fails, the Electron app shows "Agent server never came
up (60s)."

## Onboarding wizard

After the backend starts successfully, the Desktop App shows a 3-step
onboarding wizard:

1. **Choose your agent** — select OpenHands (default), Claude Code, Codex,
   or Gemini CLI. OpenHands is the right choice for local backend.
2. **Set up your LLM** — configure the provider. Click **Advanced** tab:
   - **Base URL**: `http://localhost:20128/v1` (for 9router)
   - **Custom Model**: `oc/deepseek-v4-flash-free` (9router использует префикс `oc/`, а не `opencode/`)
   - **API Key**: your 9router API key (`sk-...`)
   - Альтернативная модель: `oc/mimo-v2.5-free`
3. **Check your backend** — verifies the agent-server is reachable.
   If it shows **"Disconnected"**:
   - Host: `http://localhost:8000`
   - Type: **Local** (not Cloud)
   - API Key field: enter the **session API key** auto-generated by the
     agent-server at startup. This key is embedded in the page at
     `window.__AGENT_CANVAS_SESSION_API_KEY__` in the static build
     (visible in the HTML served at `http://localhost:8000`).

   The session API key is also visible in the startup log as
   `Secret created/updated, secret_name: OPENHANDS_AUTOMATION_API_KEY`.

If the backend is **not** reachable (step 6 failed), the "Check your
backend" page also shows "Disconnected" but the underlying cause is
a startup failure (PYTHONPATH leak or IPv6 mismatch), not a missing
API key. Diagnose with `curl http://localhost:8000/server_info` —
if that fails, fix the backend first (see "Three blockers" above);
the API key is only needed after the backend is healthy.

### Session API key format

The key is a 64-character hex string:
```
ea76abb1fc1a3579ad05f9b3cac29456610c626f528e1e7f904986ac02f4bb1a
```
It is unique per installation and generated on first start. Copied
from the app's HTML/JS source, you can paste it into the API Key
field on the "Check your backend" screen.

## Known pitfalls

- **setx NODE_OPTIONS=--dns-result-order=ipv4first** sets the var at
  USER level but does NOT affect already-running bash sessions. Use
  `$env:NODE_OPTIONS = '...'` in PowerShell or `export NODE_OPTIONS=...`
  in the same bash session.
- **Multiple Agent Canvas instances** — each new instance checks ports
  and tries to start fresh backends. Kill ALL instances and ALL 4 ports
  before restarting.
- **Agent Canvas is Electron** — `Node.js v22.12.0` bundled. Supports
  `--dns-result-order` flag.
- The frontend at `http://localhost:3001` is static-only (no API). Always
  use `http://localhost:8000` (ingress) for the full experience.
- Script patches to `dev-with-automation.mjs` are overwritten on updates.
  Re-apply after upgrading Agent Canvas.
